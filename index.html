App data served by hosts you pay

Hearth stores keys, values and files for a static web page on its own Lattice chain. You pay hosts by the day to serve it. Visitors write without an account or coin, and their browsers check every read against the chain.

Runs on Lattice mainnet; the market chain is Nexus/hearth.

Launch an app

  1. Choose who can write: anyone any key, each address only under its own keys, or each key once. The rule is fixed at launch.
  2. Pay one or more hosts up front for the days you want. If one stops, the others keep serving; renew only the ones that stayed up.
  3. Read and write from your page, hosted anywhere static:
const db = await connect({ chain: "Nexus/my-app", node, sponsors });
await db.set("r/soup", recipe);
const soup = await db.get("r/soup");

Sell hosting

In the root of a running Lattice node (5.0.0 or newer):

npx @hearthnet/hearth sell

You set a daily price. Apps pay up front; your machine makes each app's blocks. Spend what you earn on hosting, or sell it with hearth sell-coin.

What hosts can and can't do

  • Every value a browser reads is checked against your app's chain. Read from two or more hosts and a value shows only when two agree; one host alone could still serve old data.
  • A write your rules refuse is refused by every host.
  • Each host's serving record, stake and domain are read from the chain, not from the host.

Questions

What does it cost?

Each host sets its own daily price in Hearth coin. Visitors pay nothing.

How do I get Hearth coin?

Buy it on Lattice's exchange, where hosts sell what they earn.

What happens if a host stops?

The other hosts you paid keep serving. You stop paying that host when its days run out.

Can my app run SQL or server code?

No. Data is keys and values, read by key or prefix.

Is my app's data private?

No. Anyone can read it. Encrypt what should stay private before you write it.

Can I change my app's rules later?

No. They are fixed at launch.

What is a host's stake?

Coin the host burned and can never get back. It says nothing about how well a host serves; its record does.
