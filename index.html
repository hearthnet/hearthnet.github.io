Launch an app in 3 steps

Your page stays static. Hearth gives it a backend, and the hosts you hire keep it online.

1

Choose who can write

Pick one rule for your app's data. Every host enforces it, and it can't change after launch.

Rules
// who may write which keys
anyone      any key
own keys    only under your address
write once  each key set one time
2

Hire hosts

Pay one or more hosts up front for the days you want. If one stops, the others keep serving, and you renew only the hosts that stayed up.

3

Read and write from your page

Host the page anywhere static, like GitHub Pages. Visitors' browsers save and load the data directly.

JSapp.js
const db = await connect({
  chain: "Nexus/testnet/recipes",
  node, sponsors,
});
await db.set("r/soup", recipe);
const soup = await db.get("r/soup");

A host can go offline. Your page checks what it serves.

Your app's data lives with every host you hire, not one. Each visitor's browser checks what it reads, and every host enforces your rules.

Reads are checked

Every value is checked against your app's chain. Read from two or more hosts and a value shows only when two agree; one host alone could still serve old data.

Rules hold everywhere

A write your rules refuse is refused by every host, so no single host can let it through.

Hosts are judged on the record

See each host's serving record, stake and domain before you pay, read from the chain rather than from the host.

What does it cost?

Each host sets its own daily price in Hearth coin. You pay up front for the days you choose, and renew only the hosts that kept serving. Visitors pay nothing.

How do I get Hearth coin?

Buy it on Lattice's own exchange, from the Buy coin page. Hosts sell what they earn there, and Lattice checks both sides of every trade.

What happens if a host stops?

The other hosts you hired keep serving. You stop paying that host when its days run out.

Can my app run SQL or server code?

No. Data is keys and values, read by key or prefix. There are no server functions.

Is my app's data private?

No. Anyone can read an app's data. Encrypt what should stay private before you write it.

Can I change my app's rules later?

No. They are fixed at launch, so test them on testnet first.

Why do hosts put coin at stake?

To show they're serious. A host burns coin it can never get back, and you see how much before you pay. It says nothing about how well a host serves; its record does.

Is Hearth live on mainnet?

Not yet. It runs on the Lattice testnet, and hosts are paid in the market's own coin.
